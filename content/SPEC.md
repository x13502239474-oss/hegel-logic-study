# 内容写作规范（所有章节撰稿必须遵守）

本项目是一部以《小逻辑》（贺麟译，商务印书馆）为底本的系统课程网站。读者是零基础但认真的成人学习者，目标达到哲学专业本科课程的理解深度。

## 一、事实与引文纪律

1. **原文只能来自 `tools/sec.py` 输出的文本**。写引文前先运行：`python tools/sec.py 86 89`。禁止凭记忆写"黑格尔说……"。
2. 引文用容器块，长度控制在 90 字以内（可截取，用「……」标明省略），必须标节号：

```
:::src §88
如果说，无是这种自身等同的直接性，那么反过来说，有正是同样的东西。因此"有"与"无"的真理，就是两者的统一。这种统一就是变易（Das Werden）。
:::
```

3. 不得把《大逻辑》的内容当作《小逻辑》原文引用；如需补充《大逻辑》，写明"《大逻辑》第一卷第一章"。
4. 不得编造节号。拿不准就写"参见存在论「质」的诸节（§86–§98）"。
5. 学术争议必须写明"这是一种解释"、"学界另有读法"，不得把某一派观点说成黑格尔原意。
6. 参考文献只列真实存在的书，不确定就不列。

## 三、章节文件结构（必须严格遵守，构建脚本会校验）

每章一个文件：`content/chapters/chNN.md`，纯 Markdown，**不要写 front matter**（元数据由 `content/course.py` 提供）。

必须按此顺序出现下列二级标题：

```
## 本章导读
## 原著位置与文本结构
## 1｜黑格尔的生平与思想发展
（……每个课程编号一个 h2，标题与 course.py 完全一致，格式为「编号｜标题」）
## 本章总结
## 学术争议与解释分歧
## 思想比较
## 现实联系
## 延伸阅读
```

每个课程小节内部建议用三级标题组织（可用也可不用，但必须包含以下内容）：

- **问题**：这一节要解决什么困难？为什么非解决不可？
- **原文**：至少一个 `:::src §xx` 引文块（确实无原文可引的章节，用 `:::src §xx` 包裹一句原文关键词亦可；实在没有就省略，并在正文写明"本节对应 §xx 的论证"）。
- **论证**：用 `:::derive` 块拆步骤，写出"从什么前提出发 → 经过哪几步 → 得出什么"。步骤用 ①②③ 编号，每步一句判断句，不要只写"黑格尔认为"。
- **通俗**：生活化比喻或例子，但必须紧接着说明这个比喻在哪里失效（防止用例子取代论证）。
- **过渡**：这一范畴为什么必然走向下一个范畴？写出那个"逼迫"思想前进的矛盾是什么。

`:::derive` 写法：

```
:::derive 推演
① 纯存在被规定为无规定性的直接性。
② 无规定性本身即是无。
③ 于是"存在"所说出的内容与"无"完全相同。
:::
```

其他可用容器：`:::note 提示`、`:::pitfall 常见误解`、`:::compare 对照`，均以单独一行 `:::` 结束。

## 四、深度与篇幅

- 普通课程小节：500–900 字。
- 关键小节（标 ★ 者）：1200–2500 字，必须把"为什么必须这样过渡"写到读者能自己复述。
- 每章总计：4000–9000 字。宁可少写一个例子，不可少写一步论证。
- 每章"学术争议"至少给出两种有名字的解读立场（如海德格尔、阿多诺、皮平、霍耐特、泰勒、克朗纳、芬德利、霍尔盖特、邓晓芒、张世英等），并说明分歧点。
- "思想比较"至少比较两位哲学家，落到具体命题差异，不写"XX也重视辩证法"这类空话。
- "现实联系"要具体（科学中的相变、法律中的根据与理由、劳动中的目的设定、承认关系等），禁止励志化。

## 五、语言

- 学术但可读。句子可以长，但每一句要有信息。
- **禁止**"不是……而是……"句式（全文一次都不许出现）。
- 禁止"让我们"、"众所周知"、"值得注意的是"、"总的来说"。
- 禁止把辩证法写成"正题—反题—合题"套板。必须说明：这是后人对黑格尔的公式化，黑格尔本人只在《哲学史讲演录》导言里以"正—反—合"描述过，且在《小逻辑》§79–§82 用的是"知性—否定的理性—肯定的理性"。
- 禁止用"辩证地看"作为不解释的挡箭牌。
- 断语谨慎：用"倾向于"、"可以理解为"、"在黑格尔看来"。

## 六、每章必须回答的"位置问题"

每一小节结束时，读者应能回答：这个范畴在《小逻辑》的哪一部分、它从哪个范畴来、它要走向哪个范畴。把这条线索写进"过渡"段，不要留给读者自己猜。

## 七、交付自检

1. 所有 `##` 标题与 course.py 的编号、标题逐字一致。
2. 所有 `:::src` 引文都能在 `sections.json` 中检索到（去掉标点后比对）。
3. 没有未闭合的 `:::`。
4. 没有"不是……而是……"。
5. 每个小节都有"过渡"段。

## 八、概念专题页格式（`content/concepts/<slug>.md`）

纯 Markdown，无 front matter。必须依次包含九个二级标题（标题文字固定，构建脚本会校验）：

```
## 概念定义
## 原著中的位置
## 哲学背景
## 逻辑推演
## 通俗解释
## 典型例子
## 与其他概念的联系
## 常见误解
## 学术争议
```

要求：900–1600 字；"逻辑推演"必须写出该概念如何从前一范畴产生、又如何逼出下一范畴；"原著中的位置"给节号并引一句原文（`:::src`）；"常见误解"至少两条，写成"误解：……／纠正：……"；"学术争议"给两种读法。不要重复讲义原文，概念页是"专题深挖"，要有独立信息量。
